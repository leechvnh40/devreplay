## Purpose

定义一次真实面试从创建、自由回忆、定向追问到完成结构化复盘的可恢复流程，并确保事实、未知信息和 Agent 推断之间边界清楚。

## ADDED Requirements

### Requirement: 面试记录绑定当时上下文

系统 SHALL 允许用户记录公司、岗位、时间和轮次，MUST 绑定一个不可变的简历文本快照，并 SHALL 支持绑定可选 JD 文本；JD 缺失时系统 MUST 提醒但允许继续。

#### Scenario: 未提供 JD 创建面试

- **WHEN** 用户提供简历快照但未提供 JD
- **THEN** 系统提示诊断相关性可能降低并允许用户确认继续

### Requirement: 访谈采用两阶段流程

系统 SHALL 先允许用户不受打断地完成自由回忆，再根据缺失信息逐题进行定向追问；对无法回忆的内容 SHALL 记录为未知而非诱导补全。

#### Scenario: 用户记不清面试官追问

- **WHEN** 用户明确表示无法回忆某项细节
- **THEN** 系统将该字段标记为未知并停止诱导该细节

### Requirement: 复盘卡保留来源类型

系统 SHALL 为重要内容记录来源类型，包括用户陈述、粘贴原文、Agent 总结、Agent 推断、训练验证和用户修订，并在界面中可辨识。

#### Scenario: Agent 总结用户回答

- **WHEN** Agent 将一段自由回忆整理为面试回答
- **THEN** 该内容标记为 Agent 总结并链接到对应用户原始输入

### Requirement: 关键状态变更需要确认

Agent SHALL 能自动创建摘要、标签、候选诊断和训练草稿，但事实修订、诊断确认、能力状态变化和任务完成结果 MUST 经用户确认后生效。

#### Scenario: Agent 提出能力缺口

- **WHEN** Agent 根据一次回答生成缺口假设
- **THEN** 系统把它保存为待确认内容且不立即改变能力画像

### Requirement: 复盘草稿持续保存

系统 SHALL 在用户输入、卡片编辑和阶段变化时保存草稿，并在重启后从最后一个已保存阶段恢复；草稿 MUST NOT 更新正式能力画像。

#### Scenario: 复盘中途退出

- **WHEN** 用户在定向追问阶段关闭应用并重新打开
- **THEN** 系统恢复已输入内容和当前阶段且不产生正式能力证据

### Requirement: 完成状态由确定性门槛控制

系统 SHALL 仅在基本信息、自由回忆、关键题目记录、诊断处理、训练决策及证据预览均满足时允许完成；缺失信息可显式记录为未知，用户可说明无需训练。

#### Scenario: 诊断尚未处理

- **WHEN** 复盘仍包含未确认、未驳回且未保留为待验证的诊断
- **THEN** 系统禁止将复盘标记为完成并指出缺失步骤
